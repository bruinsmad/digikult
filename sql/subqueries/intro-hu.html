Allekérdezések

Néha egy kérdéshez előbb egy másik kérdésre kell válaszolni: melyik a leghosszabb dal? – ehhez előbb tudni kell, mennyi a leghosszabb hossz. Az allekérdezés egy zárójelbe tett SELECT egy másik lekérdezés belsejében: előbb lefut, és az eredménye a helyére kerül.

2Egy kérdés, két lépés

Melyik a leghosszabb dal? A MAX(hossz) megadja a számot, de a címet nem. Kézzel két lépésben menne: előbb kikeresed a legnagyobb hosszt, aztán azt a dalt, amelyiknek ennyi a hossza.

A második lekérdezésbe kézzel írtad be a 263-at. Ha holnap felkerül egy hosszabb dal, a lekérdezés már rossz választ ad. Jobb lenne, ha az SQL maga írná be a számot.

3Egyik a másikba: az allekérdezés

Írd a szám helyére azt a lekérdezést, amelyik kiszámolja – zárójelben:

Próbáld ki – át is írhatodCtrl + Enter
A belső lekérdezés fut le először: (SELECT MAX(hossz) FROM dalok) → 263.
Az eredménye a helyére kerül, és a külső lekérdezés így fut tovább: WHERE hossz = 263.

Miért nem jó egyszerűen WHERE hossz = MAX(hossz)? Mert a WHERE egyenként nézi a sorokat, egy sor pedig nem tudja, mennyi a legnagyobb érték a táblában. Az összesítő függvénynek saját SELECT kell.

4Összehasonlítás az átlaggal

Mely dalokat játszották az átlagnál többször? Ugyanígy: a belső lekérdezés kiszámolja az átlagot, a külső ezzel hasonlít.

Próbáld ki – át is írhatodCtrl + Enter
💡

Futtasd le külön is a belső részt: SELECT AVG(lejatszas) FROM dalok; Kb. 676,7 jön ki. Ezt a számot fejből sosem kellene beírnod.

Ezek az allekérdezések egyetlen értéket adnak (egy sor, egy oszlop), ezért állhatnak =, >, < mellett.

5Ha a válasz egy lista: IN

Mely dalok magyar előadóktól valók? A dalok táblában nincs ország, csak eloado_id. A belső lekérdezés kikeresi a magyar előadók id-jét – ez most egy lista (1 és 3) –, az IN pedig megnézi, benne van-e a dal eloado_id-je.

Próbáld ki – át is írhatodCtrl + Enter

Ugyanez összekapcsolással is megy, és ugyanazt adja:

SELECT dalok.cim
FROM dalok, eloadok
WHERE dalok.eloado_id = eloadok.id
  AND eloadok.orszag = 'Magyarország';
Az IN (…) utáni belső SELECT pontosan egy oszlopot adjon: azt, amelyikkel össze akarod hasonlítani a külső oszlopot.

Csoportokat is összehasonlíthatsz egy kiszámolt értékkel. Mely előadók dalait játszották átlagosan többször, mint a toplista átlaga?

8Egy érték vagy egy lista?

a belső SELECT ad…mellé írdpélda
egy értéket (egy sor, egy oszlop)= <> > < >= <=hossz = (SELECT MAX(hossz) FROM dalok)
egy listát (sok sor, egy oszlop)IN, NOT INeloado_id IN (SELECT id FROM eloadok WHERE …)

Egyetlen értéket ad az összesítő függvény (MAX, MIN, AVG, SUM, COUNT) csoportosítás nélkül, vagy egy olyan feltétel, amelyre csak egy sor felel meg (pl. WHERE nev = 'Lily Rain').

9Gyakori hibák

✗ Hibás
SELECT cim
FROM dalok
WHERE hossz = MAX(hossz);
✓ Helyes
SELECT cim
FROM dalok
WHERE hossz = (SELECT MAX(hossz) FROM dalok);

Összesítő függvény nem állhat közvetlenül a WHERE-ben: misuse of aggregate. Kell neki egy saját SELECT, zárójelben.

✗ Hibás
SELECT cim
FROM dalok
WHERE eloado_id = (SELECT id FROM eloadok WHERE orszag = 'Magyarország');
✓ Helyes
SELECT cim
FROM dalok
WHERE eloado_id IN (SELECT id FROM eloadok WHERE orszag = 'Magyarország');

A belső lekérdezés két id-t ad (1 és 3). Az = csak egy értéket tud kezelni, ezért az SQLite csendben az elsőt veszi: hibaüzenet nélkül 2 dal jön ki a 4 helyett. Listához IN kell.

✗ Hibás
SELECT cim
FROM dalok
WHERE eloado_id IN (SELECT id, nev FROM eloadok WHERE orszag = 'Magyarország');
✓ Helyes
SELECT cim
FROM dalok
WHERE eloado_id IN (SELECT id FROM eloadok WHERE orszag = 'Magyarország');

Az IN egy oszlopot vár: sub-select returns 2 columns – expected 1. Csak azt az oszlopot kérd, amelyikkel hasonlítasz.

✗ Hibás
SELECT cim
FROM dalok
WHERE lejatszas > SELECT AVG(lejatszas) FROM dalok;
✓ Helyes
SELECT cim
FROM dalok
WHERE lejatszas > (SELECT AVG(lejatszas) FROM dalok);

Az allekérdezés mindig zárójelbe kerül, különben az SQL nem tudja, hol kezdődik és hol ér véget.

10Ellenőrizd magad

Mit ad a belső lekérdezés?
SELECT cim
FROM dalok
WHERE hossz = (SELECT MIN(hossz) FROM dalok);

A belső rész csak egy számot ad: 176. A külső lekérdezés ezzel keresi meg a címet (Basszushíd).

Melyik fut le előbb?

A belső fut le először, és az eredménye a helyére kerül.

Mit írsz a pontok helyére, ha a belső lekérdezés sok id-t ad?
SELECT cim FROM dalok
WHERE eloado_id … (SELECT id FROM eloadok WHERE orszag = 'Olaszország');

Listához IN kell. (Most épp egy id jön ki, de egy lekérdezésnek akkor is helyesnek kell lennie, ha az adat változik.)

Melyik lekérdezés adja azokat az előadókat, akiknek nincs dala?

Azok kellenek, akiknek az id-je nincs benne a dalok eloado_id listájában.

Miért hibás ez?
SELECT cim FROM dalok
WHERE lejatszas > AVG(lejatszas);

Helyesen: WHERE lejatszas > (SELECT AVG(lejatszas) FROM dalok).
