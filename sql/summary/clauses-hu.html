2Egy lekérdezés, minden záradékkal

Ritkán kell mind a hét záradék egyszerre, de ha mégis, mindig ebben a sorrendben állnak:

SELECT stilus, COUNT(*)mit mutasson: oszlopokat vagy kiszámolt értékeket
FROM zenekarokmelyik táblából (vagy táblákból) olvasson
WHERE tagok >= 2mely sorok maradjanak
GROUP BY stilusmely sorok kerüljenek egy csoportba
HAVING COUNT(*) >= 2mely csoportok maradjanak
ORDER BY COUNT(*) DESCmilyen sorrendben jöjjön az eredmény
LIMIT 3;legfeljebb hány sor jelenjen meg

4Amit az adatbázis valójában csinál

Te a SELECT-tel kezded, de az adatbázis más sorrendben dolgozik:

  1. FROMfogja a táblát (több táblánál előbb párokat képez)
  2. WHEREkidobja a felesleges sorokat
  3. GROUP BYa megmaradt sorokat csoportokba rakja
  4. HAVINGkidobja a felesleges csoportokat
  5. SELECTkiszámolja a kért oszlopokat és értékeket
  6. ORDER BYsorba rendezi az eredményt
  7. LIMITlevágja a végét
💡

Ezért nem állhat COUNT vagy SUM a WHERE-ben: a WHERE idején még nincsenek csoportok, amelyeket meg lehetne számolni. A HAVING már a csoportosítás után jön, ezért ott szabad.

8Több tábla összekapcsolása

A FROM után vesszővel felsorolod a táblákat, a WHERE-be pedig beírod a párosítási szabályt: a hivatkozó szám egyenlő a másik tábla id-jével.

SELECT zenekarok.nev, koncertek.nap
FROM koncertek, zenekarok
WHERE koncertek.zenekar_id = zenekarok.id;
  • Ha egy oszlopnév mindkét táblában szerepel, írd elé a tábla nevét: zenekarok.nev.
  • Szabály nélkül minden sor minden sorral párba áll (12 × 8 = 96 sor).
  • Két táblához egy szabály kell, három táblához kettő, AND-del összekötve.
  • A szabály után jöhet minden más: további feltételek, GROUP BY, ORDER BY.

9Gyakori hibák

✗ Hibás
SELECT nev FROM zenekarok
WHERE stilus = folk;
✓ Helyes
SELECT nev FROM zenekarok
WHERE stilus = 'folk';

Idézőjel nélkül az SQL a folk szót oszlopnévnek hiszi: no such column: folk.

✗ Hibás
SELECT nap FROM koncertek
WHERE SUM(nezok) > 3000
GROUP BY nap;
✓ Helyes
SELECT nap FROM koncertek
GROUP BY nap
HAVING SUM(nezok) > 3000;

Összesítő függvény nem állhat a WHERE-ben. Csoportokra a HAVING való.

✗ Hibás
SELECT nev FROM zenekarok
ORDER BY tagok DESC
WHERE tagok > 2;
✓ Helyes
SELECT nev FROM zenekarok
WHERE tagok > 2
ORDER BY tagok DESC;

A záradékok sorrendje kötött: a WHERE mindig az ORDER BY előtt áll.

✗ Hibás
SELECT zenekarok.nev, koncertek.nap
FROM koncertek, zenekarok;
✓ Helyes
SELECT zenekarok.nev, koncertek.nap
FROM koncertek, zenekarok
WHERE koncertek.zenekar_id = zenekarok.id;

Párosítási szabály nélkül 96 sort kapsz, a legtöbbjük értelmetlen pár.

✗ Hibás
SELECT nev FROM zenekarok
WHERE orszag = NULL;
✓ Helyes
SELECT nev FROM zenekarok
WHERE orszag IS NULL;

Az = NULL soha nem igaz, ezért 0 sort kapsz, hibaüzenet nélkül.

10Ellenőrizd magad

Melyik záradék szűri a csoportokat?

A WHERE sorokat szűr a csoportosítás előtt, a HAVING csoportokat utána.

Mi a hiba ebben a lekérdezésben?
SELECT nev FROM zenekarok
ORDER BY tagok
WHERE tagok > 3;

A sorrend: SELECT, FROM, WHERE, GROUP BY, HAVING, ORDER BY, LIMIT.

Hány sort ad ez a lekérdezés?
SELECT nap, COUNT(*)
FROM koncertek
GROUP BY nap;

Minden csoportból egy sor lesz, és három különböző nap van: péntek, szombat, vasárnap.

Mit kapsz ezzel?
SELECT * FROM koncertek
ORDER BY nezok DESC
LIMIT 1;

A DESC a legnagyobbat teszi előre, a LIMIT 1 pedig csak azt hagyja meg.

Három táblát kapcsolsz össze. Hány párosítási szabály kell?

Minden kapcsolathoz egy: a három tábla két kapcsolattal áll össze.
